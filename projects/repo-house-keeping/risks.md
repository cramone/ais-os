# Risks — Repo House Keeping

| ID | Risk | Impact | Mitigation | Status |
|---|---|---|---|---|
| R-001 | infoxpert org feed `MAGIQ` holds 4 packages: FluentXml 1.0.1, Specifications 1.0.1, Specifications.Abstractions 1.0.1, Specifications.Nuget 0.9.9 (all published 2016-10) | Deleting the infoxpert feed or org (Phase 5) breaks every consumer of those packages | Confirm provenance: the likely source is infoxpert `$/MAGIQ Extensions` (TFVC), because the zip's csproj files would build 1.0.0. Find consumers. Re-host the packages or remove the dependency before infoxpert is decommissioned. Still check MAGIQSoftware and nuget.org | Open |
| R-002 | Local archive is the only copy once the source is deleted. **Extensions has now reached that point (2026-10-01)** | Losing the NAS means losing the code | Copy `Extensions.zip` and its SHA-256 to a second location (S3 or another backup) now. For future repos, do this before deleting at source. The ADO recycle bin gives a 28-day fallback | Open (urgent) |
| R-003 | Consumers could be anywhere: any source, or outside the repos (deployed binaries, other teams, source copied into other repos) | A false "unused" result leads to a deletion that breaks something | Scan every inventoried repo for package references, project references and `namespace MAGIQ.Extensions`. Ask other teams before deciding | Open |
| R-004 | The Extensions zip snapshot has no git history (D-006) | Can't blame, bisect or recover older versions once the source is deleted | Accepted. The HEAD SHA wasn't recorded before deletion. Recoverable only by restoring from the ADO recycle bin within 28 days (by 2026-10-29) | Accepted |
| R-005 | `.env` with PATs sits on the NAS share (`\\ramonenas\shared`) | Anyone with access to the share can read the tokens | Use read-only PAT scopes with short expiry. Lock the file's ACL to Chase, or move it off the share and set `REPO_HK_ENV_FILE` | Open |
| R-006 | 15 of 17 infoxpert projects are **TFVC**. GitHub Enterprise Importer only supports Git | They can't be migrated directly. Each needs converting to Git (full history with git-tfs, or ADO's tip-only TFVC→Git import), or archiving as a snapshot | Decide the conversion approach per project (pending decision) | Open |
| R-007 | `InfoXpert Legacy` and `Support Tools` (TFVC) had commits on 2026-09-09 | Active work. Converting them changes the workflow for whoever commits to them, and commits made during conversion can be lost | Freeze commits during conversion. Agree a cutover date | Open |
| R-008 | TFVC branch structure, size, and any check-in policies or gated builds haven't been captured yet | Conversion effort and history mapping can't be estimated | Pull TFVC branches and size for the projects being converted | Open |
| R-009 | The MAGIQSoftware token lacked Build, Release and Service Connections read access | Pipelines were unknown | Permissions added and inventory re-run (2026-10-01): 14 build pipelines, 6 service connections, no gaps | Closed |
| R-010 | The `MagiqSoftware` feed is the live platform feed: 204 packages, 155 published in 2026 (Magiq.Platform.\*, Magiq.AspNetCore.\* 1.1.3.x, July 2026) | GitHub's importer doesn't move Artifacts feeds. Every service that installs these packages breaks when the feed goes. **No ADO pipeline has run since 2024-03**, so the 2026 packages are published from outside ADO pipelines (GitHub Actions, or a manual `dotnet nuget push`). The source repo is still unidentified | Find the repos that produce the platform packages and how they're published. Plan the feed migration as its own workstream before any MAGIQSoftware cutover. The Performance `Nuget_Service_Connection` also points at this feed | Open |
| R-015 | 5 AWS service connections hold stored AWS credentials (Documents: aws-devops, S3. Mobile: aws-engagement-admin. MAGIQ Cloud: DevelopmentAccount, magiq-cloudformation). If they're still valid, they're an exposure | In Phase 5, revoke the matching IAM keys or roles in AWS, then delete the connections. Check whether any are still used before then | Open |
| R-016 | Pipeline `magiq-aws-waf` (MAGIQ Cloud, last run 2021-06) points at a repo id that no longer exists. `MAGIQ-Cloud-IaC` is fine: it's linked by id to the renamed `zzz-MAGIQ-Cloud-IaC` | Orphaned pipeline definition, which is noise during cutover | Delete it during ADO cleanup | Open |

| R-012 | `mgq-` name collisions in GitHub's flat, case-insensitive namespace: documents, engagement, licensing (plus deployment, extensions and foundation, but one side of each is empty or deleted) | Migration fails, or one repo overwrites the other | Settle the naming convention (e.g. include the project name) before Phase 4 | Open |
